# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the built `dist/` locally

No test, lint, typecheck, or format scripts exist. This is plain JavaScript (ESM, `"type": "module"`), no TypeScript, no ESLint config.

## Architecture

### Single-file React SPA
The entire application lives in `src/App.jsx` (~2,570 lines). Every page and component — `Nav`, `Hero`, `AboutPage`, `PCSPage`, `BaseGuide`, `NeighborhoodsPage`, `ContactPage`, `Footer`, plus shared primitives (`H2`, `H3`, `Body`, `BtnP`, `BtnG`, `Section`, `FAQ`, `InfoBox`, `PageWrapper`, `PageHero`, `Content`) — is defined in this one file. Do not split components into separate files without a reason; the single-file layout is intentional.

### URL routing (custom pushState router — no react-router)
`App` holds `const [page, setPage] = useState(() => resolvePageFromPath(window.location.pathname))` and navigates via `go(id)`, which calls `history.pushState` and updates state; a `popstate` listener syncs `page` back from the URL. A route map near the bottom of `App.jsx` (`const PAGE_TO_SLUG = { home: "/", about: "/about", calculator: "/mortgage-calculators", ... }`, with its inverse `SLUG_TO_PAGE`) plus `resolvePageFromPath` is the single source of truth for page↔path. There is also a hash handler mapping `#calculator`/`#bah-calculator` to the calculator page. Rendering is still conditional (`{page === "calculator" && <LoanCalculator />}`).

Consequence: deep links DO work (e.g., `/mortgage-calculators`, `/about` resolve to the right SPA page). Unknown paths resolve to a `notfound` page client-side; on the server, `public/_redirects` no longer has a `/*` fallback, so Cloudflare Pages serves `public/404.html` with a real 404 for anything that is not a file (added 2026-09-02). `scripts/postbuild-spa-routes.mjs` runs after `vite build` to emit a prerendered HTML shell per route so crawlers and direct hits get real HTML. When adding an SPA page, add it to `ROUTE_MAP` (and the postbuild route list) — do not assume a bare path is a 404 just because there's no matching `public/*.html` file. The prerendered `public/*.html` pages below are a *separate* SEO surface, not the SPA's routing mechanism.

### Two parallel content surfaces (updated Aug 2026)
1. **The React SPA** (`index.html` → `src/App.jsx`, now ~2,570 lines) — serves only these routes: `/`, `/about`, `/contact`, `/pcs-guide`, `/mortgage-calculators`, `/communities` (see `PAGE_TO_SLUG`). Per-route meta lives in `src/routeMeta.js`. Crawler-visible body copy + link blocks for the prerendered shells live in `src/routeSections.js`, and the 19 community links (with base groups and blurbs) in `src/communitiesData.js`, shared by `App.jsx` and `scripts/postbuild-spa-routes.mjs` so the React page and the no-JS shell can never list different communities (audit idx-04, 2026-09-02).
2. **Static HTML pages in `public/` are the PRIMARY SEO surface** — ~78 hand-maintained pages: all `public/bases/*.html` and `public/communities/*.html` plus every guide/tool page at the top level. Cloudflare Pages serves them at clean URLs (auto pretty-URLs, e.g. `public/bah-rates.html` → `/bah-rates`); `public/_redirects` 301s the legacy `.html` forms and provides the `/* → /index.html` SPA fallback. Each static page is self-contained: full head (meta/OG/JSON-LD ×6), nav, inquiry modal (POSTs to the contact worker), sticky mobile CTA, Pagefind search, GA4 + Clarity + FollowUpBoss trackers, footer. They are not generated from `App.jsx` and must be edited directly. When you change SPA content (addresses, phone, rates, base info), check whether the same content appears in a `public/*.html` page and update both.

**Civilian neighborhood pages** (`civilian-site/neighborhoods/*.html`, 11 pages, added 2026-09-02 for audit gc-content-01): generated by `node scripts/civilian-neighborhood-factory.mjs` from `scripts/civilian-neighborhoods-data.mjs` (prose + facts sourced from the military community pages, the ZIP-value post and the FLDOE 2026 grades; fair-housing design: housing stock, prices, commute, official school grades, flood/insurance only). Edit the data file, rerun the factory, then `node scripts/apply-responsive-images.mjs && node scripts/build-entity-graph.mjs && node scripts/audit-civilian.mjs`. The factory also retargets the neighborhoods hub cards and homepage chips and appends sitemap/llms entries.

**Creating a new static page:** use `scripts/page-factory.mjs` — it clones the proven template (`public/first-time-military-homebuyer.html`), swaps head/meta/JSON-LD/H1/content from a fragment file, and appends the sitemap entry. Then run `npm run og-images` and add the page to `public/llms.txt`.

**Repo quality scripts (run before deploys):** `node scripts/audit-military.mjs` (PMH twin of the civilian gate: title/description, canonical + hreflang, full OG/Twitter set, page-specific 1200x630 share card, sitemap parity incl. SPA shells, JSON-LD, sitewide furniture; runs in prebuild), `node scripts/audit-entity.mjs` (shared entity graph, 0 findings on ~200 pages of both sites), `node scripts/build-affordability.mjs --check` (one BAH-to-price model, content/affordability-2026.json; rerun without --check after a rate or BAH change), `node scripts/check-em-dashes.mjs`, `node scripts/audit-links.mjs` (0 broken; `/images/*` are deploy-time assets), `node scripts/audit-civilian.mjs` (0 findings; it now FAILS on the deleted Wikidata item Q140446886), `node scripts/sweep-school-grades.mjs --dry` (school letter grades vs `content/schools/school-grades-2026.json`), `node scripts/remove-wikidata-entity.mjs --dry`. `npm run psi` pulls PageSpeed/CrUX data (needs `PSI_API_KEY` in `.env.local`). Legal pages are generated by `node scripts/build-legal-pages.mjs`; consent text and footer links by `node scripts/rollout-consent-footer.mjs`.

**Contact worker contract** (`costin-contact` Cloudflare worker, source not in repo): requires `name`, `email`, AND `message` (400 without all three); honeypot field must be named `_gotcha`; `inquiryType` must exactly match the worker's stage map strings (e.g. `"PCS / Relocation — Buying"` — WITH the slash) or the FUB lead files as "Prospect" instead of "Lead".

### Styling
Inline styles only, driven by a design tokens object `C` at the top of `App.jsx` (`C.gold`, `C.ink`, `C.panel`, etc.) plus legacy aliases (`GOLD`, `BLACK`, `DARK`, `CHARCOAL`, `CREAM`, `WARM_GRAY`, `LIGHT`). Two font families (`SF` = Playfair Display serif, `SS` = Inter sans) are imported via a `<style>@import url(...)</style>` block inside `App`. `src/index.css` only holds a handful of global resets. No Tailwind, no CSS modules, no styled-components.

Neither worker's source lives in this repo.

### BAH data
`BAH_DATA` in `App.jsx` is a hardcoded map of MHA codes (`FL064` = Pensacola, `FL023` = Fort Walton Beach) to 2026 monthly BAH rates by pay grade. `BaseGuide` passes `bahMha` / `bahLabel` / `bahZip` per base to `BAHGrid`. Updating rates annually means editing this object; there is no data source or build-time fetch.

### Assets not in the repo
`App.jsx` references `/images/*.jpg|png` (hero, portraits, military photos, logos) through the `IMG` object. There is no `public/images/` directory in git. These assets are supplied at deploy time on the host. A missing local image is not a bug — don't chase it. `index.html` also references `/images/favicon.png` and `/images/og-image.jpg`.

### Quick-answer blocks (geo-03, added 2026-09-02)
The pages AI engines cite most carry a dated `.quick-answer` block (2-4 declarative sentences restating the page's key figure, with attribution) as the first child of `<main>`, before the CTA strip and author card. Copy lives in `scripts/add-quick-answers.mjs` (rerun to update; idempotent), the block builder in `scripts/quick-answer-lib.mjs`; both page factories and the civilian blog factory accept a `quickAnswer` field. Every sentence must restate a figure already on the page.

### Responsive images (both sites, added 2026-09-02)
Every content image gets 480/768/1200 width variants in avif/webp/jpg from `node scripts/generate-responsive-images.mjs` (idempotent; only images a page references; drops any modern-format file that is not at least 5% smaller than its jpg) and every content `<picture>` plus the two header logos are rewritten by `node scripts/apply-responsive-images.mjs` (sizes presets keyed by container class; `--only <file>` to preview one page). Run both after adding an image or a page; the variants are committed alongside the originals. Do not hand-edit srcset lists.

### Shared entity graph (both sites, added 2026-09-02)
One Person (`https://greggcostin.com/#gregg`), one RealEstateAgent (`/#team`) and one brokerage Organization (`/#brokerage`) are defined from `content/entity/entity.json` via `scripts/entity-lib.mjs`. Full nodes live only on `index.html`, `civilian-site/index.html` and `civilian-site/team.html`; every other page carries a compact @graph block (`data-entity="entity-graph:compact"`) and Article publishers use the `publisherRef` subset. Edit NAP, licenses, awards, areaServed or sameAs in the JSON, then run `node scripts/build-entity-graph.mjs` (idempotent, both sites) and `node scripts/audit-entity.mjs` (must be clean). Never hand-write those three ids into a page; generators import from entity-lib. The retired ids `pensacolamilitaryhousing.com/#agent`, `/#person-gregg`, `/#localbusiness`, `/#brokerage` fail the audit.

### SEO / agent-discoverability layer
`index.html` carries extensive meta tags, Open Graph, Twitter cards, and JSON-LD (`RealEstateAgent` schema). `public/robots.txt`, `public/sitemap.xml`, and `public/llms.txt` are maintained by hand. When adding or renaming pages, update `sitemap.xml` and, if relevant, `llms.txt`. Google Analytics is wired in `index.html` as `G-W29GHBK38M`.

## Deployment notes
Hosting is **Cloudflare Pages** (see the `_redirects` comments and the `.pages.dev` canonical-redirect snippet in every static page head). Build: `npm run build` = bump-dates → vite build → postbuild SPA shells → Pagefind index, output to `dist/`. The site serves at `https://pensacolamilitaryhousing.com/`.

## Civilian team site (`civilian-site/`) — separate deploy surface
~105 self-contained static pages (`index`, `buy`, `sell`, `reviews`, `team`, `contact`, `faq`, `neighborhoods`, `gulf-shores-orange-beach` (Alabama / Baldwin County page), `search`, `resources/*`, `blog/*`, `schools/*` + `robots.txt`/`sitemap.xml`/`llms.txt`/`_redirects`) for the civilian brand at **greggcostin.com**. NOT part of `npm run build`; deployed independently with `npx wrangler pages deploy civilian-site --project-name greggcostin --branch main --commit-dirty=true` (Cloudflare Pages project `greggcostin` → greggcostin.pages.dev). Same design tokens and contact worker as the military site; the form's `inquiryType` `<option>` strings must exactly match the worker stage map (`First-Time Home Buyer`, `Selling My Home`, `Investment Property`, `PCS / Relocation — Buying`, `General Question`). Images are absolute URLs into pensacolamilitaryhousing.com/images/. Canonicals point at https://greggcostin.com (domain is attached and live; the pages.dev canonical-redirect snippet is in every head). No em dashes in copy (the PCS inquiryType string is the sole exception). **Quality gate: run `node scripts/audit-civilian.mjs` before every civilian-site deploy — it must report 0 findings** (checks titles/descriptions, canonical+hreflang+OG, the JSON-LD entity graph, FAQ mirror, h1/walls/word-count, internal links, image alts+dimensions+CC credits, the contact-worker form contract, sitemap/robots/llms/_headers/404/IndexNow key). Per-page OG cards live in `civilian-site/og/` (generated dark+gold branded PNGs). Standing rule: every page on BOTH sites cross-links the other site (military pages: footer `data-costin-sites` line + greggcostin.com in Person sameAs; civilian pages: Military & PCS nav/footer links + sameAs) so the two domains grow in tandem.
